UNDERSTAND THE BOUNDARIES

Security explained.
Trust you can inspect.

Know how passwords are handled before you entrust them to a deployment.

Read the security model ↗

Encrypted password storage

Vault passwords are encrypted with AES-256-GCM. The server decrypts them for authorized reveals. Keynest is not currently a zero-knowledge system.

Control your deployment

Choose where to run Keynest. Your operator manages deployment security, the vault key and recoverable backups. Item labels, URLs and usernames are currently plaintext metadata.

AI is a choice

Core workflows work without AI. The current optional BYOK feature explains the built-in policy; it does not receive Vault passwords.

BEFORE YOU BEGIN

A few useful answers.

Do I need an account to generate a password?

The generator is available without an account using default rules. Sign in to use saved custom account rules. It loads the rules from the API, then generates locally.

Does Keynest change passwords on other websites?

No. Rotation is guided: change the password at the external service, then save the replacement in Keynest. Keynest cannot confirm which password an external service currently accepts.

Is Keynest independently audited?

Keynest does not claim an independent audit or certification. Review its source, documented security model and release evidence.

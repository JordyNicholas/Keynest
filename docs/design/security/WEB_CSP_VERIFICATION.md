# Web CSP production-build compatibility fixture

Part of H1 / #278, tracked by #282. The build wrapper and host configurations now define enforcement (see [delivery contract](WEB_CSP_ENFORCEMENT.md)); fixtures validate emitted policy and headers locally without deploying a public host or amending session transport.

`npm run test:build-config` in `apps/manager-web` retains the custom-API and same-origin build checks and starts a disposable headless Chromium profile for each actual production artifact. Set `CHROME_BIN` to the installed Chromium/Chrome executable when it is not `google-chrome`. The loopback HTTP fixture serves the output with the candidate policy, injects one same-origin test driver outside the packaged app, and deletes the profile after use. Node syntax can be checked without npm dependencies; actual build/browser success requires installed dependencies and the browser.

The emitted policy restricts scripts to self without inline/eval exemptions; connections to self and the build-validated API origin; object/framing/form/base capabilities explicitly. It permits inline styles for Angular/Material and the existing narrow Google Fonts style/font origins. This style exception and third-party font egress are explicit review limitations, not a nonce-based style guarantee. Unexpected CSP violations from application startup and exercised UI fail the fixture before deliberate negative probes.

The browser opens the homepage, generates a transient password, switches to the checker, toggles visibility/clears the synthetic sample, and opens the Material sign-in dialog with an overlay style check. Negative probes attempt an inline script, eval, unlisted script and unlisted fetch; the latter two must not reach the server. Only fixed outcome markers are returned. Browser DOM, generated values and diagnostic payloads must not be printed, including failure/timeout paths.

The public probe alone does not verify authenticated journeys. The authenticated gates below add creation/calendar/reveal/logout, framing controls and real loopback split-origin requests. Export/restore/rotation/edit/delete, real public Vercel/proxy behavior, all browsers and performance/font rendering remain separate evidence. Those remain H1 acceptance work before enforcement. No public host is probed. Candidate fixture success alone does not close H1 or resolve T02.

The initial real-build probe failed before negative tests with an application CSP violation. CI artifact 15119594220 (archive SHA-256 `10e9e1e85e848eb1202774331882a34292e8f0fb67face0841042f56f4446a36`) was downloaded and verified: its HTML contains an inline `onload` stylesheet handler. Disable production `optimization.styles.inlineCritical` while retaining script/style minification and font optimization, then require emitted HTML to have no inline event handlers. This changes first-paint optimization and can affect rendering performance; it avoids weakening script restrictions to accommodate the loader. Full browser confirmation of the adjusted output is required. See [Angular optimization settings](https://angular.dev/reference/configs/workspace-config#optimization-configuration).

Rollback removes the fixture/calls and restores the prior inlineCritical setting; the pre-existing production bundle checks must remain. No vault data/schema/key/session or API change is involved. A failed build may retain only public static output for one day; no browser DOM/profile/credentials are uploaded.

## Authenticated disposable Compose gate

The packaged Compose job consumes the verified same-origin public build from its own workflow run, after Angular succeeds. `node apps/manager-web/scripts/verify-authenticated-csp.mjs --disposable` requires an explicitly disposable API/PostgreSQL stack at fixed loopback port 8080. There is no configurable remote upstream. The same-origin fixture forwards API paths locally. A separately built split-origin artifact instead uses real browser requests from localhost:4200 to the API at localhost:8080 with forwarding disabled, exercising its actual CORS. Both topologies run normal and reduced-motion sessions; neither certifies a public HTTPS ingress.

The CI-only driver creates a synthetic account, signs in through the real dialog, creates a synthetic Vault item through the UI, opens/closes the Material calendar, reveals/conceals and signs out. It asserts browser session clearing and no unexpected CSP violations. Only fixed stage markers are returned; no response body, password, bearer, DOM or profile is uploaded. The normal Compose `always()` cleanup removes the disposable database; the fixture removes its browser profile. Public build artifacts expire after one day and may be replaced on workflow rerun.

The authenticated fixture uses locked `puppeteer-core` development tooling with the runner's existing Chrome, a private debugging pipe, trusted UI input and real-time waits. It does not download a browser in CI or bypass page CSP. Both normal and reduced-motion preferences are exercised with separate disposable browser profiles. The earlier dump-DOM/virtual-time driver did not establish authenticated coverage and was removed. Public fixtures retain their existing runner. Fixed auth HTTP status codes may be printed for diagnosis, never bodies or field values.

Framing has an allowed same-origin control and a blocked application-document control. Rotation, edit/delete, export/restore and real public-ingress behavior remain separate H1 browser evidence. This gate does not deploy Web CSP, change the accepted bearer transport or certify a public ingress. Rollback removes the authenticated driver/entry point, fixture API-forwarding option and corresponding artifact/CI steps, retaining the public CSP and pre-existing HTTP smoke checks.
